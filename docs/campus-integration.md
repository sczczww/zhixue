# 校园教学服务模块接入说明

知学有两个入口，共用一份业务数据、一套登录会话和师生权限。校园版参考了郑大本科教学服务平台学生侧的实际页面；辅导员端使用知学原有的模拟工作流程。当前没有连接学校生产站点、统一身份认证或教务数据库。

| 路径 | 用途 |
| --- | --- |
| `/` | 知学原版 |
| `/campus` | 校园版「全部服务」主菜单，按学生或辅导员身份分类显示服务 |
| `/module?view=mine` | 学生本人的学情画像。成绩、分类学分、预警依据和学习行动按校务查询页展示 |
| `/module?view=overview`、`/module?view=students` | 辅导员的学情总览和学生名册，可继续查看同一学生的画像、选课安排和帮扶记录 |
| `/module?view=riskcheck` | 知学下学期选课风险检查，可从学生画像或预警台账进入 |
| `/module?view=credits` | 知学按已导入记录核对学分，学校正式完成情况由页面中的教务入口查询 |
| `/module?view=reconcile` | 通过学分、路线学分和计入要求的差异，以及不写入的外语路线试算 |
| `/module?view=ledger` | 辅导员帮扶台账；服务端只返回负责范围内的学生 |

在 Windows 上双击项目根目录的 `start-campus.bat`，或从知学原版点击“校园工作台”，都先打开「全部服务」。首次体验可以浏览学生或辅导员目录，点服务后以对应的模拟身份进入。已经登录的账号看到自己的服务。业务页左上角的「主菜单」、固定的「全部服务」页签和位置路径都可以返回首页。学校其他业务可从菜单下方的「郑大教学服务平台」进入。两版的查询、学生反馈和辅导员跟进均经过同一业务接口。

## 先做不联网的联调

1. 从「全部服务 → 知学 · 学业预警与学情画像 → 下学期选课风险检查」查看当前分级预警、在读课程和需关注的下学期课程。「培养方案 → 培养方案完成情况」会打开郑大教务，登录后从「学生全部服务 → 培养方案」进入本人正式页面。
2. 同源宿主页可直接挂下方 iframe；登录后再打开时应直接显示业务内容，不应再出现另一层菜单。验收未登录、退出、角色切换、手机布局，以及辅导员不能越过负责范围。
3. 点某门课的「比较选与暂不选」，在其他课程一致的条件下检查两种安排。若组合有时段、先修或名额障碍，先展示原因。可行组合的预计缺口按在读课程和组合内课程全部通过、各类学分上限生效计算。点「让知学解释这两种安排」可核对同一组数据。

## 接学校宿主时

由校方配置教学平台可用菜单、受信域名、统一身份映射和授权的数据源。学校是身份的来源；知学不会从网页传来的学号、姓名或角色自动授予权限。没有正式身份/课程接口的演示仍使用模拟数据。项目未取得校方接口文档，下面是**知学提供的对接协议**，不是对校方接口的假设。

建议把知学部署在受控的同站 HTTPS 域名根路径（或同源根路径网关，保留文中路由及 `/assets`、`/api`）。宿主与模块须支持同站会话；只放行跨站域名不能解决第三方 Cookie 限制。反向代理须正确传递可信 HTTPS 协议信息；仅接受受信代理转发的请求头。特别留意同时同站与同源的区别。

- 上线环境使用 `ZHIXUE_DEMO=0` 和独立空数据库，通过获授权的数据导入或对接流程预置人员、专业、培养方案与师生关系。不要沿用演示库及演示账号。
- `ZHIXUE_EMBED_ORIGINS`：可选，逗号分隔的精确 HTTPS 宿主来源，如 `https://portal.example.edu`。默认只允许同源嵌入，只有 `/module` 开放嵌入。
- `ZHIXUE_CAMPUS_LAUNCH_KEY`：可选，仅配置在两个受信的服务端；使用至少 32 字节的随机密钥。未配置时换票接口关闭。请勿放入前端、代码仓库或访问日志。

**一次性入口交接：**

1. 宿主服务端完成统一登录，从自己的服务端会话取出真实用户，映射到现有知学账号。不要用浏览器提供的角色或任意学号作为映射结果。
2. 宿主服务端向知学 `POST /api/campus/tickets`：请求头 `Authorization: Bearer <服务端密钥>`，JSON 仅含 `{"userId":"已映射的知学账号"}`。返回 `ticket`、`expiresIn`（90 秒）、`entry`。只签发给已存在的学生或辅导员；不提供管理员跳转。
3. 将新 iframe 的入口设为 `https://模块域名/module?view=credits#ticket=一次性凭据`。业务页会立即清除片段，并向自身的 `POST /api/campus/session` 交换仅供知学使用的 HttpOnly 会话。每张票只能兑换一次，失效时要从宿主重新进入；校方密码不会经过知学。
4. 切换宿主身份应销毁旧 iframe，并重新签票加载新 iframe。正式上线还要联调统一退出、会话失效和导入数据更新；本项目没有对接校方单点退出。

现成宿主也可选用消息协议 `zhixue.campus.v1`，不使用它不影响独立业务页。在 iframe 加载后向准确的模块源发送 `{channel:"zhixue.campus.v1",type:"hello"}`；子页只回报当前角色、视图及演示标志。可用请求为 `navigate`（另带 `view`）、`refresh`、`notifications`、`account`。宿主必须同时核验 `event.origin` 和 `event.source === iframe.contentWindow`；不传成绩、不传密钥、不接受角色覆盖。实现示例在 `web/campus-host.js`。

第一批获授权的数据可以先用知学管理员的“数据与设置”导入 CSV。不需要让学生提供教务密码。现有模板由 `GET /api/import/template?type=records` 等接口提供，导入由管理员身份提交到 `POST /api/import`。实际字段映射可按下表与教务人员确认：

| 校方提供的数据 | 知学对应字段 | 联调时应确认 |
| --- | --- | --- |
| 学生与负责辅导员 | `students.id / major / cohort / class_name / counselor_id`，另含 `name` | 身份已映射，辅导员账号存在；不可依靠前端传入角色 |
| 专业课程目录 | `courses.id / code / name / credits / category / semester / required / major` | 先按专业和课程代码映射本地课程 ID；这里的学期是培养方案建议学期 |
| 逐学期修读与成绩 | `records.student_id / course_id / term / score / state` | 这里的学期是实际修读记录学期；未出分为空，不能填 0；学校另有记分归属学期时需先确认口径 |
| 校验完整范围 | `coverage.student_id / kind / through_term / status / source` | 有记录不等于完整；只对经核实的历史成绩或本学期选课声明完整 |

当前成绩导入会拒绝学生专业与课程目录不一致的记录。正式跨专业课程、课程替代、认定结论及校方发布的最终检查结果，均需另行映射，不能从页面截图推断。

## 数据口径

- 成绩查询保留每次修读的百分制记载成绩，待出分保持为空。[校教务〔2024〕8 号第十二条](https://www5.zzu.edu.cn/__local/9/4B/6E/0D5C783280332442F426D639EBE_CED7A822_48019B.pdf#page=5)给出了 90、85、80、75、70、65、60 分各档下限，对应绩点为 4.0、3.7、3.2、2.7、2.2、1.7、1.2，低于 60 分为 0。文件以整数列档。项目对导入的小数记载分直接比较下限，学校的小数归档取整口径由教务确认。
- 学期平均绩点先逐门换算，再按纳入课程的学分加权。任选课仍可获得修读学分，单门绩点可查，平均绩点不计其学分。课程 CSV 的可选 `metadata.courseNature` 字段接受「必修」「限选」「任选」。课程性质待核对的仅作单门展示，汇总提示实际统计范围。补考、重修需导入教务已认定的记载分，累计按同一课程的一次有效成绩核算。原有「加权均分」是项目描述指标。
- 通过学分按课程去重；再按当前专业和外语路线筛选；最后按各类别及子类的要求计算可计入部分。待确认的共享课程归属单独说明，不把差额一概当作学校的“计划外学分”。
- 试算仅改变外语路线这一条件；使用同一核算方法重算分类学分，列出改变归属的课程。它不选课、不保存路径、不代表学校批准抵扣或毕业。历史成绩未确认完整时，缺口只作估算。
- 选课风险检查单独列出当前在读、学分归属待核对、往期修读记录和下学期建议课程。已触发的预警取自知学现有分级规则与帮扶台账。风险检查和比较使用只读查询，运行检查不会生成新的预警通知。
- 比较一门课时，已保存方案优先，否则采用参考组合。两种安排共用其他课程。预计缺口只在开课、时段、名额和先修检查允许时计算。进入规划草稿后，系统保留已有的未保存编辑，并在采用比较结果前复核方案版本。
- 项目包含自有标记和样式，不包含调研账户的网页原图、真实成绩、姓名、学号、登录凭据或学校前端资源包。

## 本地验收 · 2026-11-06

- 模拟宿主完成自身身份确认后，在服务端取得一次性票据，通过 iframe 直接打开学生的学分核对业务页。实际浏览器中没有第二套导航，也没有二次登录。无效入口凭据会显示错误。
- 演示学生 `2024CS013` 在当前路线计入 101.5 学分；只试算日语路线，计入 93.5 学分。四门英语课各 2 学分，课程明细与知学助手的试算答复一致。试算前后的已保存修读选择一致。
- 用同一名大三模拟学生试算《审美鉴赏（模拟）》：选修时组合为 24 学分，暂不选时为 22 学分。在读和组合内课程均通过时，预计分类缺口分别为 33 和 35 学分。试查只读；学生主动带入后仍是未保存草稿。
- 在 1707×876 和 390×844 验证了校园工作台。手机摘要直接显示类别、计入学分和剩余学分，点开可核对要求、已获、在读与结果。
- `python -m unittest discover -s tests -p "test_*.py"`：123 项通过。包含一次性凭据的过期与重放、禁止冒充管理员、只允许指定宿主嵌入、角色权限、未出分、课程去重及子类学分上限。
