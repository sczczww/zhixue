# 组内协作与真实模型接入

本仓库包含知学独立版、校园风格版和共用后端。先从最新的 main 获取代码，再开展模型接入。

## 获取代码与交回修改

仓库：<https://github.com/sczczww/zhixue>

- 下载体验：仓库页面选择 Code → Download ZIP，解压后运行。
- 参与开发：先 Fork 到自己的 GitHub 账号，克隆自己的仓库，创建用于模型接入的分支。完成修改与测试后，向本仓库 main 发起 Pull Request（合并申请）。
- PR 说明写清修改内容、测试使用的模型、已通过的实际场景和剩余问题。负责人核对并合并后，再统一更新线上网站。
- API Key 在本机配置；提交内容限于源码、测试和说明，保留对密钥、数据库和运行日志的忽略规则。

## 在电脑上启动知学

需要 Python 3.12+。Windows 双击项目根目录的 `start.bat`；首次启动会创建环境并安装依赖。已有本机知学服务时，先确认运行的是当前目录的版本。

也可以使用：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

默认访问 <http://127.0.0.1:8766>，首次运行会创建独立的模拟数据库。

真实模型联调使用上述普通本机模式。`--public-demo` 和线上共享演示会关闭管理员配置并固定使用本地学情工作流。

## 配置真实模型

1. 在本机登录页选择管理员，或使用演示账号 `admin`、密码 `demo123`。
2. 打开“数据与设置 → 模型接入”，将运行模式改为“远程大模型”。
3. 填写支持工具调用、兼容 Chat Completions 的服务 Base URL、模型名称和自己的 API Key。项目会向 Base URL 下的 `/chat/completions` 发送请求。
4. 先点“保存配置”，再点“测试已保存配置”。
5. 切换学生模拟账号，进入知学助手，验证真实工具调用流程。

模型名称和地址以服务商当前提供的信息为准。网页填写的 Key 仅存在当前服务进程内存中，重启后需要重新填写；也支持 `ZHIXUE_API_KEY` 环境变量。

## 首轮需要跑通的场景

使用模拟学生 `2024CS013`，将回答与页面实际数据对应核对：

| 场景 | 要核对的结果 |
|---|---|
| 解释当前预警 | 实际调用画像或预警工具；对象、课程、数字和引用与查询结果一致 |
| 检查下一学期选课 | 调用开课、课程组合或选课风险工具；说明假设与模拟数据范围 |
| 连续追问 | 沿用正确的学生、课程和学期，不混入其他学生信息 |
| 生成行动草案 | 先展示可检查的草案，点击采纳后才进入行动清单 |
| 服务失败 | 错误可见，已有查询结果保留；回退到本地工作流时明确显示实际模式 |

连接测试返回成功只证明模型端点能回答。真实接入还要观察模型选择工具、系统执行工具、结果回传模型后继续查询或回答的过程，并区分远程成功与本地回退。

## 主要代码位置

| 文件 | 作用 |
|---|---|
| `server/assistant.py` | 模型配置、远程请求和连接测试 |
| `server/agent_runtime.py` | 工具定义、权限检查、多轮调用、引用与事实核对、行动草案 |
| `server/selection_risk.py` | 下一学期风险与单门课程对照试算 |
| `tests/test_agent.py` | 工具调用、权限和异常回退的模拟测试 |
| `web/workspace.js`、`web/independent.js` | 对话、草案和独立版页面交互 |

可运行现有模拟测试，再另外记录真实模型的联调结果：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_agent.py" -v
```

模拟测试通过、真实服务连通和实际回答正确是不同的验证项，请分别记录。当前项目尚未宣称真实学生风险预测准确率或真实校园帮扶效果。
